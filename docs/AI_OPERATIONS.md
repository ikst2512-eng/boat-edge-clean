# BOAT EDGE CLEAN — AI運用基盤（段階導入）

目的：予想精度・データ真正性・表示/操作性・運用障害を継続的に評価し、**検証を通った改善だけ**を本番反映する。既存の1ページ4タブを維持し、旧画面/重複ワークフローは増やさない。

## 現時点で実装した範囲
- `ai_operations.py` は既存の時系列研究結果を読み、Top3/5/10の候補とベースラインを比較する**読み取り専用のゲート**。
- `research_chronological_calibration.py` の検証制約をそのまま尊重する。研究サンプルを正式的中率として表示しない。
- 自動昇格・予想変更・本番デプロイはしない。結果はGitHub Actionsの成果物として残す。
- **LLM API、自動再学習、サイト変更エージェントは未実装。** この段階を「AI導入完了」と呼ばない。

## 次の実装段階
1. 予想/出走表/展示/結果の各取得について、取得時刻、ソース、原本ハッシュ、欠損理由、締切前の証拠を一貫して監査する。
2. 監査済みの事前予想だけで日付分離の学習・検証・ホールドアウト比較を行う。Top3/5/10に加え確率較正、データ欠損率と遅延も計測する。後付け予想は不採用。
3. LLMをサーバー側のオプション機能として導入し、監査結果の要約、障害原因分析、修正PR案を生成する。秘密鍵はRender/GitHubのsecretで管理し、ブラウザには渡さない。外部送信対象は最小化する。
4. 修正PRはCI/スマホ実ブラウザ/公開APIの検証に合格して初めて承認候補とする。モデル切替と本番デプロイは承認・ロールバック可能な段階的操作にする。
5. 管理者向け運用状況は既存サイト構造に適切に統合し、一般ユーザーの予想画面へ未検証のAI説明を混ぜない。

## 運用上の不変条件
- 予想時点を越える情報は特徴量に使わない。
- オッズは確率順位を変更しない。
- 学習用/検証用/本番用データを分離し、検証結果で同じホールドアウトを繰り返しチューニングしない。
- 自動生成物に「成功」の表示を許すのは独立した根拠がある場合だけ。
- AIの自動コード修正/マージ/破壊的削除はデフォルト禁止。
- AI導入による改善は、導入前後の実測で評価する。
